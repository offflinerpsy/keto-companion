# Interface acceptance contracts

Food search: human name/state/source/count/continuation; internal stable ID only as machine key. Parse: resolved named entries plus unresolved input and visible result receipt. Pantry/diary/dish proposal: typed Russian summary and action-specific confirmation, current task surface, clear saved receipt; stale/expired/revoked cannot apply.

External barcode/label: bounded request→attributed candidate→review missing/basis/allergens→prepare change→apply once→pantry/next-step. Cancellation leaves state unchanged. Timeout/unknown paid dispatch does not auto-retry; same request identity reconciles first. Session/consent changes discard late output. Camera denied/unsupported offers photo/manual route.

GI/GL/measurement tool outputs: numeric only from compatible known inputs; missing fields explained in Russian. Owner health data does not enter public datasets/logs or admin summaries.

Own composition: select confirmed named ingredients and state, enter edible grams for the whole dish and servings, then review whole-dish/per-portion values with field coverage. Cancel retains the draft and changes nothing; explicit confirmation saves once as an observational composition. Factual consumed portions can enter the diary without claiming a checked meal plan. A partial or unmapped ingredient remains excluded from exact-plan/generated-method acceptance; unknown net carbohydrate stays unknown in the daily budget.

Source search/review Return handling cannot dispatch paid recipe generation. Lists remain bounded and fully reachable; choosing another named product invalidates pending source details. Final allergen confirmation uses Russian labels.
