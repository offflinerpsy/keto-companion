# Исполнение 0.2.1

Облачный сервис в Azure выполняет расчёты, проверки и запись состояния. `keto_chat` вызывает отдельный deployment `keto-terra-61`; это не переключает модель внешнего чата ChatGPT и не заменяет его голосовой движок. Серверная модель получает только необходимый контекст после согласия; API-запросы используют store=false. Это не обещание отсутствия провайдерского журналирования или хранения.

MCP endpoint: https://keto-companion-ay-20261107.azurewebsites.net/mcp. Плагин использует собственный OAuth issuer сервиса с PKCE S256, затем Microsoft Entra как проверку личности. Публичный client ID — идентификатор, не секрет. Закрытые ключи, токены, allowlist и личное состояние никогда не включаются в пакет навыков. Обычный веб-вход Entra и MCP-токен имеют разные границы доступа.

Серверная база — приватный Azure Blob с условной записью по версии. При недоступном хранилище нет молчаливого переключения на временный SQLite в production. При сбое нельзя обещать, что изменение или ограничение сохранено. История/JSON-экспорт и повторное чтение используются для сверки; не исполняй пользовательские JSON/CSV как программу.

Скрипты `scripts/keto_core.py` и `scripts/keto_export.py` сохранены как воспроизводимый расчётный материал библиотеки 0.1.1; их отдельные функции не означают, что все они доступны через текущий облачный API/UI. `scripts/self_check.py` проверяет неизменность файлов библиотеки, а НЕ облачное соединение или медицинскую пригодность. Папка `server/` в старом account checkpoint 0.1.2 — архив исходников до текущего OAuth; не запускать её как актуальный сервер. Текущие исходники: /Users/alexyarosh/Projects/keto-companion-azure, версия сервиса 0.2.1. В пользовательском чате никаких локальных установок Python не требуется.

Интерактивный MCP resource обслуживает сервер; это не старый демонстрационный HTML. В конкретном ChatGPT аккаунте/устройстве нужно отдельно проверить авторизацию, отображение и работу инструментов. Протокольные тесты не равны такому подтверждению.
