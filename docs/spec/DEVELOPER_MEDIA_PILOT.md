# Developer and media pilot · 0.7.0

CF-DEV-MEDIA-08 is a source implementation. Local synthetic checks do not establish a deployed container, real Sol call, family release or device acceptance. The parent owns provisioning, image validation and release. Earlier staging receipts describe earlier builds.

The existing owner's More entry and explicit Nutrition / Development selector open a separate technical form. Nothing is inferred from nutrition conversation or imported source content. The owner checks “technical description only” and approves the exact text before one Sol high request. The request contains that text, a baseline and three permitted UI source files; its state is null. No profile, diary, photo, source attachment or chat history is included. A person can still type personal information into the technical box: the checkbox is an explicit attestation, not an automatic personal-data classifier.

The patch can change only app.css, help.html and developer-extension.js. It contains at most three UTF-8 text files and 60,000 content bytes. Worker and trusted runner independently enforce paths, hashes and bounds. The build creates a deterministic source manifest and sanitized archive in ignored build directories. Generated outputs, secrets, personal data, environments, delivery archives and logs are excluded. The UI-only generated snapshot module is versioned with the source so the trusted gate can import it before its final build; the tar/manifest remain ignored build inputs. A missing or mismatched snapshot fails closed. The snapshot must be regenerated from the final reviewed tree before the parent builds the image. Its baseline excludes generated bundles and documentation to avoid a circular hash.

D1 migration 0007 adds dev_settings, dev_jobs and sanitized dev_events. Enabling requires an explicit owner POST, for at most 24 hours. Defaults are three reserved generations per UTC day and 5,000 maximum output tokens. One serverwide lease is active. Request IDs cannot be replayed; failures do not automatically refund uncertain model reservations or recursively retry. Artifacts use only the private UPLOADS binding under developer/. They remain tied to the creating owner's session. Disable cancels active tasks; expired or revoked state cannot accept a late model/test result. Cancellation does not assert that an already delivered model request avoided a charge.

The DEVELOPER_RUNNER service binding calls DeveloperRunner on the isolated keto-companion-developer-runner Worker. External fetch returns 404. The API deployment descriptor is [api-deployment.json](../../developer-runtime/api-deployment.json); this project uses the parent's native Cloudflare API, not Wrangler. The parent provides the pinned image, DO namespace and migration, max one instance, the two matching baseline/digest variables, and a ten-minute cleanup cron on the main Worker. Cleanup is lazy on owner developer requests as well. Physical R2 deletion depends on successful cleanup execution; expiry immediately blocks access. No production credential enters the container.

The root-owned runner validates the image source manifest, creates a fresh workspace, applies only allowed files and executes candidate code as uid/gid 1000. Protected sources and tests are read-only. Fixed stages are syntax, build, product and python, with a shared 240-second deadline, bounded output and process-group cleanup. No command comes from the model. A passing result needs the exact stage order, zero exits, positive product/Python test counts, baseline, patch hash and image digest. Sol saying “passed” is never accepted as a test receipt. The Docker/network-none and actual Cloudflare checks belong to the parent.

Only a tested patch can be downloaded as a unified diff or shown in the private iframe. The iframe has scripts but no same-origin, forms, popups or top navigation permission; the returned document uses network-denying CSP and synthetic fixtures. It renders actual candidate styles, help and the narrow extension entrypoint, not the full authenticated app. This is a bounded UI preview, not family-app end-to-end validation. The candidate never executes in the admin document. Closing a task removes its artifacts. There is no publish endpoint or production overlay: “Publication is a separate verified release.” GitHub-hosted startup remains a separate historical execution issue; native Cloudflare Builds can run the trusted gate without GitHub Actions. The gate and public icon artwork are parent-owned.

Chat uses the existing attachment controller for picker, paste, drop, remove and URL load. Plain text paste remains native; one image is selected and a multiple-image notice explains the cap. Account and topic changes invalidate pending attachments. URI drops offer the URL form without fetching automatically. A plain URL is not represented as a seen image or read webpage.

The explicit URL action discloses the remote request. Only images.unsplash.com, images.pexels.com and upload.wikimedia.org are supported in this release. HTTPS/443, no userinfo, bounded redirects, a narrow transform-query list, fixed-resolver all-A/AAAA checks, streamed size bounds, MIME and magic checks are enforced. Each redirect is revalidated. This deliberately restricted host list addresses the unpinned-DNS limitation; universal arbitrary URL support is not claimed. Fetch is bounded to 8 seconds and 4 MiB; the existing signed sanitizer transport accepts at most 1,000,000 input bytes here. Larger images require file upload and local compression. Azure sanitizes with null state, consent/session is checked again, and nothing is saved by the link endpoint. Sending an image-only message includes real image content in the Azure multimodal request; grams and nutrients are not invented.

The favicon routes serve the parent's SVG, ICO and raster files with real MIME/signatures. Apple and manifest icons remain separate sizes of the same artwork. Four bottom tabs are preserved. Owner and media controls stay in normal flow; desktop/mobile visual checks are still required from the parent.

## Recovery acceptance and release boundaries
The first Docker dependency image failed because Node required libatomic.so.1. The pinned image now copies that system library; original failure evidence is retained. A real Linux Docker acceptance ran with network disabled, read-only root, synthetic source and uid1000 candidate. Fixed syntax/build/product/Python stages passed. This does not certify a future changed baseline or live Cloudflare RPC; final release records the exact source/image. Runtime publication still ends at private preview and downloadable diff; no GitHub write/deploy token is supplied to generated code.

Direct image URLs are restricted to the listed public CDNs and explicit loading. JPEG/PNG/WebP and GIF first frame are normalized to metadata-free JPEG. Plain image-URL paste offers a loader but does not fetch or send automatically; unrelated text paste remains untouched. The optional URL field cannot block ordinary chat submission. Late developer responses after account change are discarded.

A manual encrypted registry-credential transfer was blocked and not retried; no credential was returned. Normal release is attempted only through the already-authorized native Cloudflare build and official cf CLI, keeping credentials inside that platform. A permission error stops the release; no new token/role is granted to work around it.

Native Docker-in-Docker dependency installation uses the documented host network only while building the reviewed pinned image: bridge-DNS failed in the build environment. The actual candidate tests still use `--network none`, and the deployed Container class has `enableInternet=false`. No model-supplied Dockerfile, package list or command is accepted.
