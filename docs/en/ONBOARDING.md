# Guided onboarding and explained targets · 0.5.0-guided-pilot

KETO-ONBOARDING-05 extends the existing app. New and partially configured members and admins start at the actual missing stage: Consent, About you, Restrictions, Targets. Unknown medical answers remain unknown. Reference recipes are available without completing setup; personalized menus retain clinical gates. Returning configured users retain their intended route. Existing manual targets are never silently replaced.

Baseline requires actual age, height, weight, measurement date, timezone, an explicitly selected equation coefficient, described activity, goal and eating mode. Female/male is an equation coefficient, not inferred gender; non-selection permits reference/manual use, not an automatic estimate. Blank numeric fields do not submit defaults. Decimal commas, large step buttons, keyboard controls and local noUiSlider 15.8.1 are supported. Sliders edit fields without network calls, recalculation or saving per drag.

Server policy starter-v1 reuses keto_core.validate_baseline and estimate_energy. The browser and model never produce canonical numbers. Mifflin–St Jeor (ENGINE01, 1990, 498 adults aged 19–78) estimates resting energy only: 10W + 6.25H − 5A + 5 male / −161 female. Core maintenance uses the resting value before its displayed rounding. Activity 1.4/1.6/1.8 is an approximate product mapping, separate from Mifflin and not the NIDDK/Hall dynamic model.

Automatic pilot scope: full screen without holds/flags, age 19–78, BMI 18.5 inclusive to 35 exclusive, loss only at BMI ≥20. Gain needs an individual plan. These are product eligibility boundaries, not diagnoses or universal danger claims. Pregnancy, breastfeeding, SGLT2, T1D, renal/other disease, eating-disorder and unknown-medication flags fail closed.

Maintenance uses the estimated center; gentle loss subtracts min(300 kcal,10% maintenance), a conservative product policy rather than an NIH prescription or the historical AHA/ACC/TOS rule. Targets are center ±5%, rounded to nearest 10 kcal with halves up. The displayed ±10% maintenance uncertainty is an interface assumption, not a confidence interval. A lower bound below 1200 female / 1500 male does not get silently clamped: choose maintenance or individual review. These floors are not universal safe minima.

Tentative protein is 1.2–1.6 g/kg actual current mass, rounded outward to 5 g. Leidy 2015 supports weight-management discussion with heterogeneity/adherence caveats; maintenance carryover is product policy. Ideal/adjusted weight is not substituted. Explicit eating modes use 100 or 50 g TOTAL carbohydrate, do not guarantee ketosis and are not a medical 4:1 diet. Net is separate and never automatically subtracts polyols. Fiber is 14 g/1000 kcal center, rounded to whole grams; increase gradually with individual tolerability. Saturated fat 10% retains existing general library policy; no extra oil, electrolytes or supplements are prescribed.

Baseline and target proposals require explicit confirmation. Target preview is a visible page with inputs, formula, intermediate results, sources, warnings and replacement differences. The internal core status “agreed” means user confirmation, not clinician approval. Manual changes show user-edited provenance. Changes to baseline, screen, medication, allergies, goal/mode stale computed targets and block menus/exports until reconfirmed; name/UI edits do not medically invalidate them. Thirty-day/5% review prompts never adapt calories automatically. Existing manual targets retain prior behavior and clinical gates.

If catalog search finds no solution, the app shows the actual constraints and recipe/support actions without weakening allergy, protein or fiber limits. Heuristic failure is not mathematical proof of infeasibility.

Allowlisted hash navigation supports Back/Forward, secondary Back controls, direct recipes from Chat/Menu and recipe-dialog Back without personal URL data. Main tabs avoid excessive history. Navigation does not save answers or repeat private requests on history traversal; logout clears private route/UI state. Dictation, topics, PDF, reminders and Google invitations are preserved.

Knowledge cards use authored summaries and dated links from the existing sources, evidence matrix and calculation sources; no original corpus rewrite, full article text or full-RAG claim. New sources/assumptions live in versioned service/data/starter_policy_sources.json. Retracted S18 is excluded from support; S19 is integrity control only.

Authenticated HTTP/edge keto_guidance supports status, preview, baseline proposal and recomputed target proposal by preview_hash. Identity comes from authentication, not browser fields. The hash binds saved medical inputs, user and policy; client candidate numbers are not authoritative. The legacy MCP interface excludes this operation. No D1 schema changes: choices/provenance live in the existing private document.

The build retains 13 modules with local vendored noUiSlider JS/CSS, license and source hashes. CSS combines vendor with public/app.css. No dependency install, Mac browser/GUI, cloud mutation, commit or push is performed by this writer. Parent runs tests/browser/setup.spec.mjs in the isolated container and performs runtime/device/security/clinical acceptance and release. Local tests are not independent visual or medical acceptance.
