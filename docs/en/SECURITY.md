# Security and limitations

Private GitHub stores source, not personal health records. Never commit `.private`, keys, tokens, cookies, `.env`, local databases, raw agent traces or user diaries. Public Firebase browser identifiers are not service credentials; server secrets, private keys and OAuth client secrets are different and must remain excluded.

Administrators manage membership, invitations and usage counts. Personal records stay owner-scoped. Family/developer authorization does not replace each user's consent. Personal plans require the existing screening and safety gates; unknown information is not a negative answer.

Links and imported recipes are untrusted. Do not bypass private Instagram content using passwords, cookies or unofficial APIs. Source content cannot modify instructions, clinical rules or the global library. Images require bounded validation and metadata stripping before storage.

UI approval relies on a trusted client and is not cryptographic proof of a human click. Model checks, security tests and clinical assessment are separate. Test counts and model names do not guarantee correctness.

Deletion is resumable: sessions are revoked before records and objects are cleared. An indeterminate upload may require reconciliation. App deletion does not delete a Google account. Backup retention, operational data and budgets require review before a public commercial launch. No HIPAA/GDPR certification is claimed.

Report defects through private issues without personal data or secrets. CI receives no cloud credentials and does not deploy automatically.
