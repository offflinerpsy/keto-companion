# Mobile release candidate 0.4.0-mobile-pilot

Task KETO-MOBILE-006 extends the existing mobile/chat-first branch. This is tested source, pending parent runtime, deployment, container visual QA, real account/device speech, sharing and clinical acceptance. The legacy Azure plugin keeps its 0.2.1 semantics and version.

The home screen is chat with four bottom tabs: Chat, Menu, Diary and More. More contains recipes, sources, onboarding, reminders and settings. Inputs have inline descriptions. Confirmed profile, diary and menu changes remain separate user actions. The viewport follows visualViewport, with safe-area padding, a dedicated chat scroll area and keyboard-aware navigation.

Photos can be picked or pasted, decoded and compressed before transmission, previewed and removed. Unsupported HEIC requires a JPEG/PNG export. Photos cannot establish exact mass or complete ingredients. Dictation starts only on a user click with consent: up to 60 seconds and 1 MB. Stop, cancel, page hiding and logout release microphone tracks. The server decodes bounded local MP4/WebM/WAV streams using a pinned installed ffmpeg, rejects silence/overlong input, and calls the existing managed-identity Azure gpt-transcribe deployment. Audio stays in memory. The transcript becomes an editable draft and enters chat history only after Send. This is not a voice conversation.

Accepted current safe plans can generate actual Cyrillic PDF files with ingredients, portions/states, preparation steps and shopping, excluding screening, diary and private source text. Prepare the PDF first, then click Share PDF or Download. The separate share click preserves user activation; Telegram is a user-selected share-sheet destination, not an automatic send. Missing verified NotoSans fonts fail explicitly. JSON/CSV/HTML backup/import remain under Advanced.

Topics share confirmed profile preferences but have separate recent context and recipe-choice IDs. Limits are 12 topics, 60 messages per topic and a 200 KB aggregate serialized history cap; oldest messages are trimmed. Existing chat lazily becomes main. Topic deletion/clearing removes its messages and service reply receipts; the Worker invalidates prior cached task replies. Profile remains. Unsaved drafts require discard confirmation on topic changes. Request hashes include non-main topic IDs.

Recipes use known catalog IDs and validated temporary include/exclude/time filters. Hard allergies and confirmed exclusions always apply. Inexact matches explicitly state what differs; they never invent nutrition. Temporary boredom does not create permanent dislikes. Explicit requests to remember preferences produce confirmation proposals. A follow-up “second option” uses only that topic's prior recipe IDs and never accepts a menu automatically.

Up to 20 reminders support a title, IANA timezone, local time and weekdays or a one-off date. Templates fill the editor without saving. Upcoming/overdue and completion appear while the app is open. Calendar .ics exports use VTIMEZONE/RRULE/VALARM and stable private UIDs. After importing, Calendar and its notification permissions control delivery. App edits do not synchronize imported events. Calendar recurrences are bounded to two years, within the supplied timezone transitions, and then require a renewed import. WebPush and automatic Google synchronization are out of scope.

Build with `node cloudflare-saas/build.cjs`. Both Worker variants and the exact hashed multipart inventory are regenerated. PNG icons are base64 TEXT modules decoded on response. The deployment script validates the manifest against imports; account and secret controls stay unchanged. No offline private-data cache is introduced.

New topics/reminders/transcription operations use authenticated HTTP/Worker and the signed bridge; the legacy MCP list and MCP execution exclude them. Legacy HTTP accepts optional thread_id and recipe filters. Transcription shares existing member/global Worker cost counters, reserves before provider calls, stores no audio/transcript job response, rejects repeated completed requests, and discards output after session/consent changes. Unknown upstream effects retain conservative accounting.

Parent prepares pinned OFL fonts using `python scripts/prepare_pdf_fonts.py --directory runtime-fonts --download`, or verifies supplied files without --download. Fonts remain ignored in Git; Azure release packaging requires and includes verified runtime fonts. Dependencies are pinned; runtime downloads are not used.

Parent runs tests/browser/playwright.config.mjs only in a Linux container. It uses actual application DOM/CSS with synthetic qa/mobile-fixtures.json for 440×956 DPR3, 390/375 widths, landscape, keyboard height, large text, paste/photo and share interactions. The fixture server and auth stubs are test-only and are not imported by deployment code. These checks do not establish real iPhone speech, popup, sharing or Calendar behavior. See qa/MOBILE_IMPLEMENTATION_RESULT.json for observed checks and limitations.

## Verified transcription route
This Azure resource uses the deployment-specific audio API, version 2025-03-01-preview. Its v1 deployment lookup returned404 and is not used. MP4/WebM/WAV are decoded in memory with only pipe/fd protocols enabled; Linux uses a seekable anonymous RAM descriptor for ordinary MP4. Transcription is returned as an editable draft.
