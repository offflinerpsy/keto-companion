# Архитектура

Cloudflare Worker обслуживает сайт и API. D1 хранит пользователей, приглашения, сессии, согласия, состояние питания, задания, счётчики и происхождение источников. Приватный R2 предназначен для загруженных материалов. Google/Firebase отвечает за подтверждение личности, но успешный вход сам по себе не предоставляет членство в приложении.

Сервер определяет пользователя из проверенной сессии. Клиент не может передать произвольный subject или роль. Пользовательские данные разделены по владельцу. Приглашение ограничено сроком и почтой; его просмотр не расходует приглашение, принятие требует отдельного действия.

Вычисления и Azure Terra вызываются через ограниченный HMAC-подписанный мост `/internal/keto/compute`. Новый полный профиль передаётся на время вычисления в память Python-процесса. Его постоянное хранение остаётся в Cloudflare; Azure Blob используется только для ограниченных метаданных защиты от повторов. Существующий Azure-клиент 0.2.1 сохраняет свой прежний режим хранения; молчаливой миграции между ними нет.

Worker резервирует задание и квоту до платного вызова. После ответа повторно проверяются пользователь, сессия, согласие и версия данных. Повтор завершённого request ID не должен повторно вызывать модель. Неизвестный результат таймаута не превращается в успешную запись.

Модель распознаёт намерение и формулирует ответ. Числа, ограничения и изменения записей проверяет программа. Изменять можно разрешённые настройки с предварительным показом и подтверждением, но не произвольный код, лекарства или клинические правила.

Версии независимы: данные 0.1.1, приватный плагин 0.2.1, исходный SaaS 0.3.0. Зафиксированная сборка и её SHA-256 перечислены в `artifacts/files_manifest.json`.
