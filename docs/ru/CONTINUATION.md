# Продолжение другим разработчиком или агентом

Сначала прочитайте `AGENTS.md`, `docs/CURRENT_STATUS.json` и открытую GitHub Issue. Сверьте текущую ветку/коммит и файлы evidence. Старые отчёты не переопределяют новое состояние.

Работайте в этом репозитории. Один исполнитель и одна активная задача. Для изменения — отдельная ветка, маленький коммит с причиной, результат теста и PR. Не смешивайте новые функции, настройку входа и публичный выпуск в одну задачу. Не делайте force-push, не меняйте видимость и не запускайте браузерные клиенты без нового разрешения.

Контрольная точка восстановления: `docs/evidence/RECOVERY_STATE.json`. Она историческая; текущий статус хранится отдельно. Локальный `qa/RECOVERY_STATE.json` содержит машинно-специфичные сведения и не должен превращаться в бесконтрольный лог в GitHub.

Следующий согласованный этап после GitHub — KETO-RELEASE-002: staging фиксированной сборки, без новых функций. Критерии: receipt, совпадение хешей, доступность публичных страниц, защита приватных маршрутов и честное указание статуса Azure compute. Следующая задача выбирается только после закрытия этой.
